# 사고 기록 (troubleshooting)

## 이 폴더는 무엇인가

**한 사건을 끝까지 파고든 기록**이다. `docs/daily/` 와 성격이 다르다.

| | 목적 | 단위 |
|---|---|---|
| `docs/troubleshooting/` | **깊이** — 왜 그랬는지 끝까지 | 사건 1건 |
| `docs/daily/` | **흐름** — 그날 무슨 일이 있었는지 | 하루 |

## 파일 이름

`<날짜>_<짧은식별자>.md` — 예: `2026-07-30_accept-header.md`

## 🔴 필수 6필드

모든 문서는 아래를 **전부** 갖는다. 하나라도 비면 나중에 쓸 수 없다.

| # | 필드 | 왜 필요한가 |
|---|---|---|
| 1 | **증상** | 무엇이 이상했나. 관측된 사실만 |
| 2 | **원인** | 코드/데이터 어디인지 **위치까지** |
| 3 | **조치** | 무엇을 바꿨나 |
| 4 | **근거** | 🔴 **분모를 밝힌 실측**. "좋아졌다"는 근거가 아니다 |
| 5 | **상태** | ✅해결 / 🟡부분 / 🔴미해결 / ⏸보류 |
| 6 | **재발 방지** | 같은 유형을 다음에 어떻게 막나 |

### ⚠ 5번(상태)이 가장 중요하다
**미완료를 완료로 적으면 그것이 나중에 기준이 된다.**
"이미 고쳐졌다"를 전제로 다음 판단을 하게 되고, 그 전제가 틀리면 전부 틀린다.
확실하지 않으면 🟡 로 적는다.

### ⚠ 사실은 **저장값으로 확인한 뒤** 적는다
함수명 하나를 잘못 적어 12시간을 쓴 전례가 있다.
문서를 쓰기 전에 `grep` 으로 이름이 실재하는지 확인한다.
