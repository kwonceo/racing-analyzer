# Accept 헤더 누락 — oddspark 9초 지연

| | |
|---|---|
| **발생** | 2026-07-30 (원인은 그 이전부터 상시) |
| **상태** | ✅ **해결** |
| **영향 범위** | oddspark 배당 수집 전체 |

## 1. 증상
수집 사이클 1회가 **31~41초** 걸렸다. 30초 틱 주기보다 길어 사이클이 밀렸다.
느린 요청이 **8/8(100%)** 로 전부였다.

## 2. 원인
`_keirin_fetch` 가 보내는 요청에 **`Accept` 헤더가 없었다.**
Akamai 봇 탐지가 `Accept` 없는 요청을 **타르핏(고의 지연)** 으로 처리한다.
브라우저는 항상 `Accept` 를 보내므로, 없는 요청은 자동화로 판정된다.

🔴 **서버가 느린 것이 아니라 우리가 봇으로 분류된 것이었다.**
"상대 사이트가 느리다"로 결론냈다면 영원히 못 고쳤다.

## 3. 조치
`app.py` 에 `_ODDSPARK_HEADERS` 상수를 두고 `_keirin_fetch` 가 사용하도록 했다.

```python
_ODDSPARK_HEADERS = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)",
    "Accept": "*/*",
}
```

⚠ **동시성은 올리지 않았다.** 헤더 한 줄로 해결되는 것을 병렬화로 덮으면
상대 사이트 부담만 늘고 원인은 그대로 남는다.

## 4. 근거 (⚠ 분모 명시)
| 지표 | 수정 전 | 수정 후 |
|---|---|---|
| 사이클 1회 | 31~41초 | **2.28초** |
| 느린 요청 | 8 / 8 (100%) | **0 / 20 (0%)** |

## 5. 상태
✅ **해결.** 실측으로 확인됨.

## 6. 재발 방지
- 🔴 **원칙 10 신설**: *"외부 사이트가 느리면 헤더를 의심한다."*
  상대가 느린 것이 아니라 **우리가 봇으로 분류된 것**일 수 있다.
- 새 외부 수집 경로를 추가할 때 `Accept` 를 반드시 포함한다.
